# 差异化矩阵（DIFF-MATRIX）

> 目的：**防"换名复用"**。胆道癌与肝细胞癌同属消化/肝胆，最近的样板就是 `liver-cancer-workbench` v0.3.4。
> 下表逐项说明"哪些照抄、哪些必须不同、不同在哪一行代码/哪一个字段"。
> 写在"刻意不同"里的，**不许在后继开发里被统一掉**——那是被评审过的决定，不是遗漏。

## 一、与最近样板（`liver-cancer-workbench` v0.3.4）的逐项对照

| 维度 | 肝细胞癌（样板） | 胆道癌（本项目） | 判定 |
| --- | --- | --- | --- |
| 主脊结构 | **双轨并列**：A 肝功能储备 / B 肿瘤负荷 | **双轴并列**：梗阻-黄疸轴 / 肿瘤-治疗轴（不加总、不互推） | 刻意不同（见 D2） |
| 分期 | BCLC 与 CNLC 并存不换算 | **不做自动分期**，只记录医生说的分期与出处 | 刻意不同（见 D1） |
| 解剖分型 | 无（HCC 不细分部位） | 四型：GBC / iCCA / pCCA（附 Bismuth-Corlette）/ dCCA | 新增 |
| 可切除性 | 有（切/消融/TACE/移植多路径） | **只记录，不判定**；门静脉/肝动脉受累、残肝体积只作记录字段 | 刻意不同（见 D3） |
| 独立照护页 | 无 | **`drain` 胆道引流照护页**（PTCD / ENBD / 支架） | 新增（本癌种最有差异化的一页） |
| 黄疸 | 作为一个症状/指标 | **独立一级页 `jaundice`**：胆红素趋势 + 三症状（瘙痒/尿色/陶土便） | 新增 |
| 主指标 | AFP | **总胆红素**（一图秀默认线）；CA19-9 次之 | 刻意不同（见 D4） |
| 肿瘤标志物分级 | 有（AFP 走趋势） | **CA19-9 明确不分级**（CTCAE 无条目） | 刻意不同（见 D5） |
| 基因/靶点 | 无独立模块 | **`treat` 内嵌"检测位点三态"**（FGFR2 / IDH1 / HER2 / BRAF / NTRL / MSI） | 新增 |
| 指南 | 有 G1–G3 已签 | **未拿到原件前不做**（M8） | 刻意不做 |
| 营养页 | 无 | 无（并入 `care` 场景条目） | 一致（见 D6 说明） |

## 二、与胃癌样板（`gastric-workbench`，体例基准）的对照

| 维度 | 胃癌 | 胆道癌 |
| --- | --- | --- |
| 营养/进食 | **有**「营养支持」独立页（术后怎么吃、体重怎么称） | **不设**独立页：胆道癌的营养问题多由梗阻或术后引起，属场景条目而非主任务 |
| 手术前后 | 围手术期重点是进食通路 | 围手术期重点是**减黄 + 引流管**（PTCD/ENBD 带管回家） |
| 一级页数 | 9（含营养） | 9（含 `drain` 与 `jaundice`，不含营养） |

> 刻意相反的两处（胃癌设营养页 / 胆道不设）**不许统一**：两癌种的"患者每天要动手记的东西"不同。

## 三、五条刻意的差异（必须能在代码里指出来）

### D1 不做自动分期

- **场景**：患者拿到报告，想确认"我这是几期"。肝族能自动摆出 BCLC/CNLC 两套，因为 HCC 的分期体系与治疗路径强绑定；胆道癌的分期（AJCC 第 8 版）按部位分四套（胆囊/肝内/肝门/远端），T 定义各不相同，且**分期本身不直接决定路径**（还要看血管受累与残肝体积）。
- **功能**：`type` 页只做"分期记录位"——`stage_system`（AJCC8 胆囊 / AJCC8 肝内 / AJCC8 肝门 / AJCC8 远端）、`stage_value`、`stated_by`、`stated_on`。页面写「分期由医疗团队判断，这里只记录」。
- **验收**：全仓搜索不到任何分期计算函数；`type` 页无"自动分期"控件；schema 里 `stage_value` 是文本不是枚举。

### D2 双轴并列不加总

- **场景**：肝族患者要同时看"肝还撑不撑得住"和"肿瘤多大"；胆道癌患者要同时看"堵没堵、黄不黄"和"肿瘤与治疗走到哪"。
- **功能**：`jaundice`（梗阻-黄疸轴）与 `treat`（肿瘤-治疗轴）各自独立；`dash` 上两块并排，**不做合成评分、不做加权、不互为前提**。
- **验收**：`dash` 的两块之间没有"综合分""整体状态"这类合成元素；两轴的数据在 schema 里没有外键依赖。

### D3 可切除性只记录不判定

- **场景**：门诊里"能不能切"是最高频问题，也是最不可自动化的——肝门部涉及门静脉/肝动脉受累、需算残肝体积（FLR）。
- **功能**：`resectability_note` 表：`said_by` / `said_on` / `verbatim`（原话要点）/ `next_step`。页面写「这里只记录医生说过什么」。
- **验收**：该表无布尔字段 `resectable`；页面无"可切除/不可切除"徽章；硬约束 M5 单测可查。

### D4 一图秀默认总胆红素

- **场景**：复查时患者最先看的是"黄不黄"，而 CA19-9 波动大、易被误读为进展。
- **功能**：`chart` 默认数值线＝总胆红素；CA19-9 为次线（可切换）。
- **验收**：`demo-data.js` 里 `chart.default` 指向 `tbil`；ui-parity 断言首屏两条线的顺序。

### D5 CA19-9 不分级

- **场景**：想给"这个数高不高"一个答案。
- **功能**：只给趋势 + 参考范围对照；卡片无徽章，背面写「该项不适用 CTCAE 分级」。
- **验收**：`ctcaeCoveredCodes()` **不包含** `ca199`；单测断言传入 CA19-9 返回 `not_graded`（不是 `needsUln`，也不是给级）。

### D6 `dash` 现状卡：四行事实，零判断（2026-10-24 新增，源自 U6）

- **场景**：用户原话「太多不同的检测报告看不懂，病人病情怎么样了？」——他要的是一句"现在怎么样"，而这句在临床上是判读。
- **功能**：`dash` 顶部固定四行，模板填空、每行强带出处：① 最近一次关键指标（值 / 日期 / 与上次差 / 参考范围）② 最近一次影像结论**原文引用** ③ 当前治疗第几周期（起止）④ 最近一次医生说的分期与可切除性（谁说的、哪天）。无数据时该行写「暂无记录」。
- **验收**：`dash` 文案里搜不到 M9 禁用词（稳定/好转/恶化/进展/缓解/良好/不乐观/预后/控制住了/问题不大）；四行每行都能点开看到来源记录；单测喂一个"指标涨了"的档案，断言渲染结果里不出现任何判断句。

### D7 报告只做索引，不做解读（2026-10-24 新增，源自 U6）

- **场景**：化验单、CT 报告、病理、出院小结四类纸混在一起，不知道哪份查什么、哪份还有用。
- **功能**：`labs` 二级「报告」= 一行一份文件（日期 / 类型 / 谁开的 / 结果原文首行 / 已进趋势 or 仅存档）+ 每类一句**检查项目通用说明**，同屏标明「说明的是检查项目，不是你的结果」。与 `imaging` 页分工：这里是"有哪些纸"，`imaging` 是"纸上结构化的评估事实"。
- **验收**：页面搜不到"报告说没事/有问题"类判读句；每份文件都能看出是否进了趋势；`document.feeds_trend` 与 `chart` 的实际取数一致（单测交叉断言）。

### D8 方案依据：医生原话 + 指标 + 指南条目（2026-10-24 新增，源自 U5）

- **场景**：用户原话「家属和患者对'后续治疗策略'的重要指标依据和影响判断依据，不了解指南，不知道该怎么理解。」
- **功能**：`treat` 二级「方案依据」，一次讨论一条：医生理由原话 / 勾选的涉及指标（带日期值）/ 指南条目（机构+版本+页码齐全才显示，缺则整条「未引入」），并标注**是谁记的**（患者 / 家属 / 医生小结），不合并成"共识"。
- **验收**：缺 `version` 或 `page` 的指南条目插不进库（`NOT NULL`，已实测）；页面无「推荐 / 首选 / 应该用」；"这个方案适不适合我"不产生任何自动回答，只显示固定句子「这一句需要问你的医生」。

## 四、照抄不改的部分（免得重造）

- 顶栏三段式与 AI 五态、面板 `customFrame` 外壳与拖动、一图秀画布常量与末点避让、3D 卡翻转、`[hidden]` 规则、字号三档、窄宽六条规则。
- 四条数据契约、`ORDER BY rowid` / `ord` 习惯、`ref_low`/`ref_high` 落库、`needsUln` 三态徽章。
- 检查链与装机链路（含 `mkdirSync`、`apply()` 懒重试两条硬约束 H20/H21）。
