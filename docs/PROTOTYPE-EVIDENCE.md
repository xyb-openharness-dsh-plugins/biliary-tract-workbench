## 一、这一版是什么

`prototypes/v0.2/` 是**交互原型**，不是业务实现：

- 四件套：`index.html` / `style.css` / `app.js` / `demo-data.js`（数据由 `npm run build:proto` 从 `demo/build-demo-data.mjs` 生成，与演示库同源）。
- 十一页 + 九个二级页签，覆盖 `docs/FEATURE-INVENTORY.csv` 的 56 条功能（ACC-001–ACC-056）。
- 不接 DSH、不接 AI、不落库。刷新即重置；标注"原型不落库"的按钮只给一句提示。
- 两套合成档案：`p1 周慧兰`（肝门部 pCC · PTCD 减黄后手术）与 `p2 郭长林`（胆囊癌术后 · 影像见新发结节 · 无引流）。

## 四、三条边界在原型里的落点

1. **事实层**：所有数字旁边都有日期与出处；"与上次差 +2"是减法，不解释方向。
2. **解释层**：凡是需要解释的地方（分级对照、检查项目说明、指南条目）**故意显示"未引入"**，因为库里没有带页码的原件。这三处是这一版最想让人看见的地方——空白是规则在起作用，不是没做完。
3. **判断层**：全页只有一种出口，棕色浅底那句「这一句需要问你的医生」。代码里没有把指标翻译成结论的函数。

## 五、已知未做完（G2 评审时请一并看）

1. **不落库**。新增打标、加问题、改周期都是假的，`flag-save` 只弹提示。
2. **无 AI**。AI 面板是静态清单 + 本地词表自检，不调模型。
3. **图表交互只到"选中 / 翻面"**。没有十字光标、没有 tooltip 联动、没有导出。
4. **移动端只做了降级布局**（≤900px 单列），没有逐屏实测。
5. **指南 / 检查项目说明两条解释通道全部为空**，等带页码的原件。
6. **`p2` 的"下一步方案讨论"是一次计划中的门诊**，原型不预测结果——这是刻意的。
7. **临床试验 10 条全是合成条目（`DEMO-` 开头）**，没有登记平台原件与真实中心；上线前必须接 ClinicalTrials.gov / ChiCTR，并显示核验日期。
8. **没有后台同步任务**：真实版本的试验状态、中心、截止日期需要定时拉取并写 `trial_track_event`，原型只有静态演示事件。

## 六、怎么重跑

```bash
npm run build:proto                  # 重新生成 demo-data.js
python3 -m http.server 8771 --bind 127.0.0.1   # 或任意静态服务
npm run probe:proto                  # 需要 NODE_PATH 指向工作区 node_modules
npm run check                        # 语法 + 冻结合同 + 文案红线 + 包结构
```

文案红线的扫描范围已加入 `prototypes/v0.2/app.js`（但不含同目录的 `demo-data.js`——那里是报告原文，属事实层）。原型主程序里 5 处"说明不写什么"的元用途行已加 `wording-ok` 显式豁免。
