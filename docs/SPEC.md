## 零、总原则：三层信息边界（2026-10-24 确认）

> **医疗结论是医生的判断；信息解释与提醒是工作台的支持能力。**
> —— 项目维护者 2026-10-24 明确同意这条划法。本节是全项目的**最高约束**，M9 / M10 / A7–A9 都是它的实例；与本原则冲突的功能一律不做。

| 层 | 内容 | 工作台能不能做 | 必须带的出处 |
| --- | --- | --- | --- |
| **① 事实** | 某个值是多少 / 哪一天 / 谁说的 / 哪份报告写的 / 与上次差多少 | ✅ **能做**，可以计算差值、排序、画趋势 | 每条都要能点回到来源（文件 / 录入 / 医生原话的日期与说话人） |
| **② 解释** | 这个指标是什么、这项检查查什么、指南原文怎么写的、CTCAE 分级表怎么规定的 | ✅ **能做**，但只解释「东西本身」，不解释「你的情况」 | 机构 + 版本 + 页码（缺一即不显示，M8）；通用说明必须同屏写「说明的是项目本身，不是你的结果」 |
| **③ 判断** | 病情好坏、稳定还是进展、方案优不优、要不要停药、是不是复发、预后如何 | ❌ **不做**，一句都不生成 | 固定出口：「这一句需要问你的医生」 |

**这条线的由来**：U6 原话是「病人病情怎么样了？」——字面就在要第 ③ 层。给了就是替医生下结论，错一次就可能让人误判轻重；完全不给，等于拒答用户最想问的问题。所以把答案限定在 ①②，把 ③ 明确交回医生。

### 提醒（属于第 ② 层，不是第 ③ 层）

提醒是本项目最容易越界的地方——它天然带"该做什么"的暗示。判据只有一条：**提醒的触发条件来自用户自己的东西，还是来自医学阈值判断。**

| 可以提醒（触发条件是用户的记录或日期） | 不可以提醒（触发条件是对病情的判断） |
| --- | --- |
| 「距上次复查 92 天，你上次记的是 12 月复查」 | 「你的指标提示病情进展，应尽快就诊」 |
| 「这周引流量有 3 天没记」 | 「引流量下降说明管子可能堵了」 |
| 「你 9 月问过的这个问题医生还没回答，可带去下次门诊」 | 「CA19-9 升高要警惕复发」 |
| 「这次化验的 ALP 是 2.4 倍参考上限（该化验单自带上限 125 U/L），是否处理请咨询你的医疗团队」 | 「ALP 超标，需要护肝治疗」 |

写法要求：**陈述事实 + 指明这是谁的标准 + 指向医生**，三样缺一不可。禁止出现「应」「需」「建议」「警惕」「注意排除」。

**适用范围**：本条对本项目与**之后新建**的病种工作台生效。已有工作台（肝 / 乳腺 / 食管 / 胃 / 结直肠等）**不回溯改造**——2026-10-24 维护者决定「不用，这个对本项目和之后的新项目生效即可」。老项目缺的是「稳定 / 好转 / 进展 / 缓解」这类判读词，属已知存量风险，记在这里，不在本轮处理。

**机器执行**：`scripts/check-wording.mjs` 把上面两张表变成扫描，已接入 `npm run check`，命中即 `exit 1`。它只扫会进用户屏幕的源码（`public/`、`src/`、`lib/client.js`），不扫文档与演示数据——文档必须能引用这些词，演示里的“复发”是医生原话。

## 问题、用户与最小闭环

### 五重信息落差（U1–U3 未核实；U5、U6 有一条非正式输入，见 `PATIENT-FLOW.md` §四）

1. **「我这算哪一期、还能不能切」说不清** —— 胆道癌的可切除性判断随影像与黄疸处理动态变化，患者手里往往只有一个「先减黄再说」（**U1，未核实**）。
2. **带管生活没有说明书** —— PTCD/ENBD/胆道支架术后，引流液颜色、量、发热、脱管这些日常判断，患者只能靠微信群问（**U2，未核实**）。
3. **化验单看不懂趋势** —— 总胆红素、CA19-9、肝功能一串数字，单次值没有意义，趋势才有（**U3，未核实**）。
4. **报告太多，越看越不知道"现在到底怎么样"** —— 化验单、CT 报告、病理、出院小结四类纸混在一起，不知道哪份查什么、哪份还有用；最想问的一句是「病人病情怎么样了」，但既没人给一句话，也不该由工作台给判断（**U6，2026-10-24 一条转述输入**）。
5. **看不懂治疗策略的依据，不懂指南** —— 医生换方案时只记住结论、没记住理由；网上搜到的指南说法互相矛盾，不知道该信哪个、也不知道自己该对照哪一条（**U5，2026-10-24 一条转述输入**）。

> **第 4 条是本版最危险的诱惑**：它字面上就是在要一个结论。产品线划在——
> **回答「现在是什么状况」（事实 + 原话 + 日期），不回答「这算好还是坏」（判读）**。
> 见 ADR A7 与硬约束 M9。

### 用户

- **主用户**：已确诊胆道癌（肝内胆管癌 / 肝门部胆管癌 / 远端胆管癌 / 胆囊癌）的患者本人，或其主要照护家属。中位年龄偏大，常见「家属代为记录」。
- **次用户**：照护者（子女为主），负责带资料、问医生、管引流。
- **明确不是用户**：医生（不做临床决策支持）；未确诊者的筛查人群（不做早筛）。

### 最小闭环

| 环节 | 输入 | 动作 | 输出 | 失败恢复 |
| --- | --- | --- | --- | --- |
| 建档 | 诊断名词、确诊日期、当前治疗阶段 | 选四型之一（M6），填日期 | 一条 `profile`，页面顶栏显示「当前阶段」 | 型别不确定 → 允许选「未明确」，不强制 |
| 记录 | 化验单数字、引流观察、用药 | 逐条录入，带单位与化验单自带参考区间 | 趋势线 + 指标卡 | 单位缺失 → 不落库并提示；`ref_high` 缺失 → `needsUln`，不猜 |
| **看懂** | 四类报告（化验 / 影像 / 病理 / 出院小结） | 登记文件、标「已进趋势 / 仅存档」；看不懂的点打标 | `dash` 现状卡四行事实 + `labs` 报告清单 | 无来源 → 该行显示「暂无记录」，**不留空也不编** |
| **理解依据** | 一次方案讨论 | 记医生原话 + 勾涉及指标 + 关联指南条目 | 一条 `依据记录`（带日期与出处） | 指南条目缺版本/页码 → 整条「未引入」，不许占位 |
| 准备 | 上述记录 | 生成「下次复查前要问的三件事」 | 一页可打印清单 | 数据不足 → 清单降级为「先补哪些记录」 |

**成功标准（可验收）**：用户在复查前一天，能在 5 分钟内说清四件事——① 最近一次总胆红素和 CA19-9 是升还是降；② 这三个月有没有出现需要提前就诊的情况；③ 手里有没有一份能直接给医生看的清单；④ **被问「现在怎么样」时，能否指着 `dash` 现状卡的四行念出来（每行都带日期与出处）**。第 ④ 条只要求"念得出事实"，不要求"下判断"——工作台没资格给那个判断。

## 方案与 ADR

| ADR | 决策 | 备选与被否原因 |
| --- | --- | --- |
| **A1 单机优先** | 数据只落本地 SQLite，不联网同步 | 云同步（要处理逐文件同意、凭据、脱敏，收益对单人使用不成比例）；纯浏览器存储（换机即失，且无法做迁移） |
| **A2 customFrame 自绘外壳** | `customFrame=true`，宿主把原生会话节点作为 `conversation` prop 交给我们 | 标准分栏 + 页面自绘会话栏 = 两个「AI 对话」（家族已实证）；`customFrame=false` 时服务里没有拖宽/收起接口 |
| **A3 九页分列，不做首页大聚合** | 概览 / 记录 / 趋势 / 引流 / 复查 / 用药 / 资料 / 提问 / 设置 | 单页仪表盘（胆道癌信息维度跨「梗阻-黄疸」与「肿瘤-治疗」两轴，塞一页必然靠折叠，反而不如分列） |
| **A4 不自动分期** | 只记录「谁说的 / 哪天 / 原话」，不推算 AJCC/BCLC 类分期 | 自动分期需要影像原文与病理，工作台拿不到；错分期比不分期危害大（M5） |
| **A5 CA19-9 不做分级** | 只画趋势 + 相对基线变化幅度，不套 CTCAE | CTCAE 无 CA19-9 条目，硬套等于编造分级（M3） |
| **A6 演示数据 2 套 × 6 个月** | 肝门部（带 PTCD）+ 胆囊癌（术后化疗）各一套 | 一套不足以覆盖「带管 / 不带管」两种主路径 |
| **A7 现状卡只填事实，不判读** | `dash` 现状卡固定四行：最近关键指标（值/日期/与上次差/参考范围）、最近影像结论原文（引用）、当前治疗周期、最近一次医生说的分期与可切除性（谁说的、哪天）。**模板填空，每行强制带出处** | ① 生成一句总结（"目前病情稳定"）——那是判读，违反红线且错一次就误导；② 不给现状卡——U6 的核心诉求就是这句"现在怎么样"，完全不给等于拒答；③ 让 AI 自由生成——同一份数据每次措辞不同，无法验收 |
| **A8 报告只做索引，不做解读** | `labs/报告` 一行一份文件（日期/类型/谁开的/结果原首行/是否进趋势）+ 一句**检查项目通用说明**，并标明「说明的是检查项目本身，不是你的结果」 | ① 报告结论翻译（"报告说没事"）——等于替医生判读；② 直接接 AI 读片——未验证能力不宣称；③ 只做文件柜不标注——用户仍不知道哪份进了趋势 |
| **A9 指南只给条目，不判"你符合哪条"** | `treat/依据` 每条含来源/版本/页码 + 节奏 + 并列口径；缺版本或页码 → 整条「未引入」 | ① 做"符合度对照"（你符合 III 期标准）——需要病理与影像全量，且这是临床判断；② 不引指南只说"问医生"——用户明确说了"不了解指南，不知道怎么理解"，等于没解决 |

5. 不做 CA19-9 或胆红素的分级告警（A5）
6. 不做多患者管理（一人一台）
7. 不做与医院 HIS / 检验系统的对接
8. **不给"病情结论"**：不生成「稳定 / 好转 / 进展 / 良好 / 不乐观 / 预后如何」任何判断句，现状卡只填事实与出处（A7、M9）
9. **不回答"这个方案适不适合我"**：不比较方案优劣、不排推荐顺序、不判定"你符合指南哪一条"（A9、M7、M8）
10. **不做临床试验入组判定、不替用户联系中心、不排序成"最该去的那一个"**（M13；只做逐条三态对照与收藏跟踪）

## 临床试验匹配（`trials`，2026-10-24 追加）

**为什么有这一页**：胆道癌可靶向位点集中（FGFR2 融合、IDH1 R132、HER2、MSI-H、BRAF 等），试验条件常按"分型 × 位点 × 治疗线数"组合，患者与家属很难把手里一叠报告逐条对上。工作台能确定的是"记录里写了什么"，所以这一页只做对照，不做推荐。

**三个二级页签**：

1. **匹配**（TRL-01/02/05/06/07）：上面列"用来对照的病理特点"8 项（病理类型 / 分期 / 可切除性 / 系统治疗线数 / 总胆红素×ULN / 白蛋白 / ECOG / 基因检测），每项带日期与说话人，没记的写「未记录」；下面是逐条对照的试验卡，每条条件三态（符合 / 不符合 / 待确认），硬性不满足的单列一组。符合度 = 符合项 ÷ 已对照项，未知按 0 计，同屏写明"不是入组资格、不代表效果"。
2. **检索**（TRL-03/04）：按关键词、病理类型、治疗场景、状态筛条目；「与我相关」不在这里判断，避免把"存在但与我无关"的选项藏掉。每条可看条件原文与中心。
3. **收藏与跟踪**（TRL-08/09/10/11/12）：收藏后进入跟踪，状态分「在跟 / 准备问 / 已归档」；跟踪线只记外部注册信息变化（状态、中心、截止日期、条件修订），每条带来源与日期；待确认项可一键转成复查问题。

**三条硬边界（M13）**：

- 条目必须带登记号、状态、核验日期；没有核验日期只能显示「未核验」，不得显示「招募中」。
- 未知项永远留成「待确认」，不用阴性或符合填充；ECOG 这类工作台没有的字段，一律显示"未记录"，不猜。
- 不做入组判断、不排"最该去的那一个"、不预测结果；收藏只是"我盯着这条"，不是"我要去这条"。

**当前状态**：`prototypes/v0.2/` 里的 10 条试验全部是合成演示数据（`DEMO-` 开头），只用于验证规则与交互。上线前必须接 ClinicalTrials.gov / ChiCTR（或医院公开招募信息），写入真实登记号、状态与核验日期；`trial_match` 只存派生快照，可回放"当时按什么算的"。
